Alpha Exploration Log
Ideas tried during the 23 Jul alpha-exploration pass, partly inspired by the
CookieAlgorists Algothon 2023 winning-presentation write-up and partly from
this project's own "worth trying if revisited" backlog. All methodology
below is in-sample only: days 1-500 of prices.txt, no peeking at
prices_unseen_hidden.txt (501-750). Where a train/test split is used, both
halves are still strictly inside days 1-500. Follow the same rule as
everything else in this project: a real effect shows a plateau across
neighbouring parameter values and consistent block-level signs; a fitting
artifact shows a lone spike or a sign flip. Nothing below was promoted to a
real 501-750 check because nothing cleared this in-sample bar convincingly
enough to spend that look.

---

### 1. Trend-smoothed lead-lag input
Inspiration: CookieAlgorists' final model combined each predictor's own SLR
trend slope (not its raw last-day move) with a cross-stock coefficient.
Tried feeding a k-day OLS slope of each name's ALGO+PC1-residualized return,
instead of the raw single-day value, into the existing dense lead-lag
matrix L (which is fit on a strict one-day lag).

Method: L fit once on days 1-450 (in-sample). Held-out check on days
451-499. Compared raw single-day input against k-day slope inputs,
k in {3, 5, 8, 12}, via cross-sectional correlation and sign-hit-rate
against next-day realized residual returns.

Result: raw input beat every smoothed variant, monotonically worse as k
grew (avg cross-sectional correlation 0.095 raw vs 0.037 / 0.053 / 0.040 /
0.020 for k = 3 / 5 / 8 / 12; hit rate 52.9% raw vs 51.2-52.2% smoothed).

Verdict: REJECTED. L is fit on a one-day lag, so smoothing the input blurs
exactly the timing a fast-decaying (~1-week half-life) signal needs. Would
reconsider only if the lag structure of L itself were changed to something
slower.

### 2. Long/short asymmetry
Inspiration: CookieAlgorists found their universe punished buying and
therefore only traded one side of their composite score.

Method: checked the dense lead-lag signal's hit rate conditional on
predicting up vs down, and the raw cross-sectional return distribution of
the 49 non-ALGO names, days 1-500.

Result: predicted-up hit rate 53.1% vs predicted-down 52.7% (essentially
symmetric). Pooled daily-return skew 0.025 (near zero). Drift across names
symmetric around a near-zero mean (top-5 positive drift +0.0006 to +0.0015,
bottom-5 negative -0.0015 to -0.0019).

Verdict: NO EXPLOITABLE ASYMMETRY FOUND. This generator does not share the
lopsided universe CookieAlgorists traded in. Not a rejection of a tested
mechanism so much as a "the precondition for this idea does not hold here."

### 3. Gated cross-sectional reversion
Background: this project's own old notes flagged cross-sectional reversion
(fade a name vs. the peer mean) as having a real but unstable in-sample edge,
and explicitly listed "combine it with a stability filter" as worth trying
but never done. Grafted on the trailing-self-PnL throttle already validated
for the gray tier (Sigma7c's GTHR: gm = clip(mean/(2*se), 0, 1)).

Method: fully causal walk-forward simulation, lookback in {2,3,4,5} x
throttle window in {off, 60d, 90d}, days 1-500, 50-day block stats.

Result: lookback=3 + 60-day throttle looked like a genuine improvement in
isolation (Sharpe 1.30 to 1.46, ungated to gated, with visibly smaller
losing blocks). But neighbouring lookbacks did NOT confirm it: lookback=2
gated got worse (0.91 to 0.59), lookback=4 gated got much worse (0.76 to
0.15), lookback=5 gated also got worse (1.34 to 0.98). Only lookback=3
improved under gating.

Verdict: REJECTED. Lone spike, not a plateau -- the same failure signature
that killed relrev-h2=15 and MOM_H=20 in earlier rounds of this project.

### 4. Kalman-filtered hedge ratio, seed pairs
Inspiration: CookieAlgorists' first strategy family (pairs trading) was
built around Kalman-filtered hedge ratios, later abandoned by them as "too
much" complexity for the benefit. Never tried in this project at all before
now.

Method: standard 2-state Kalman filter, state = [alpha_t, beta_t] as a
random walk, Q = delta/(1-delta) * I2, R fixed from warmup-period OLS
residual variance. Applied to the same 7 seed pairs the existing static
rolling-OLS + EWMA-vol mechanism trades, as a one-variable ablation. Delta
picked on days 120-350, confirmed on days 350-499.

Result:
  baseline (existing mechanism): train Sharpe 6.48, test Sharpe 7.25
  Kalman delta=1e-2:  0.00  /  0.00
  Kalman delta=1e-3: -0.39  / -1.79
  Kalman delta=1e-4:  2.07  /  1.13
  Kalman delta=1e-5:  3.87  /  2.62
  Kalman delta=1e-6:  4.98  /  4.52
  Kalman delta=1e-7:  5.13  /  5.44
Monotonic: performance rises steadily as delta shrinks toward "beta barely
moves at all," but even that extreme never catches the baseline.

Verdict: REJECTED, and unusually cleanly -- six orders of magnitude all
point the same direction (less adaptivity is better), and the least-
adaptive extreme still loses to the existing static refit. The seed pairs
do not need or want continuous re-estimation.

### 5. Single-name idiosyncratic SLR momentum
Inspiration: CookieAlgorists' SLR-momentum stage (rolling-OLS trend slope,
traded directionally). Applied here to each name's ALGO-residualized price
LEVEL (not raw price, which would just be a disguised beta bet already
known dead; not the second factor/PC1, which was already tested).

Method: rolling-window OLS slope, window in {5,7,8,10,12,15,18,20,25,30,40},
both follow and fade directions. Direction and window picked on days
120-350, confirmed on days 350-499.

Result: no plateau anywhere. Sign flips between adjacent windows and
between train/test at the same window (e.g. window=12: train Sharpe +0.39,
test -0.83). Windows that looked spectacular held out (18, 20: test Sharpe
2.59, 2.81) sit directly next to windows that did not (15, 25: test Sharpe
-0.03, 0.33).

Verdict: REJECTED. Textbook noise, not a real effect.

### 6. Kalman-filtered hedge ratio, gray tier
Follow-up to #4: hypothesis was that the gray tier (a population known to
rewire ~73% between windows, per this project's own measurements) might
benefit from beta adaptivity even though the stable, hand-verified seed
pairs did not.

Method: 19 gray pairs found once using data through day 350 (matching what
a real rescan would have seen), held fixed while comparing baseline
(expanding-OLS + plain-std z, matching the real scan_gray trading code)
against the same Kalman filter as #4, delta swept.

Result (important methodological note): an initial train(120-350)/
test(350-499) split looked promising -- Kalman test Sharpe 1.62 vs baseline
test Sharpe 0.39. But re-checking across the FULL 15-block sequence
(days 120-499) reversed this: baseline wins 9 of 15 blocks overall (Sharpe
2.08) vs Kalman's 6 of 15 (Sharpe 1.28). The original "test slice" had
simply landed on a rough patch for the baseline (blocks 11-12 and 15); it
was not a real, generalizable Kalman edge.

Verdict: REJECTED. Also a useful reminder to always check the full block
sequence, not just whatever single split was chosen first -- an arbitrary
split point can manufacture an apparent win.

### 7. algo_ridge_z standalone ablation (Zigma10/11/12)
Not a new idea, a verification task: this 6-feature ridge regression
(breadth, mean/median non-ALGO return, ALGO's own return, two interaction
terms; ridge lambda, rolling window) sits inside the Zigma models' ALGO
forecast at a heavy 5.0x weight, and had never been isolated and tested on
its own.

Method: traded standalone (sign(algo_ridge_z), full $100k cap, nothing
else in the book), full block breakdown across days 120-499, plus a 3x3
neighbourhood sweep of lambda in {3,10,30} x rolling window in {120,180,250}.

Result: as-coded (lambda=10, roll=180): Sharpe 1.09, 11/15 blocks positive.
Every one of the 9 neighbourhood configs was POSITIVE (Sharpe 0.05 to 1.29,
no sign flips) -- more robust in direction than any of #1, #3, #5, #6, #8.
But concentration risk: block #12 alone (one 25-day stretch) prints 430-474
across nearly every config and accounts for roughly 40% of the as-coded
strategy's total average PnL. Excluding that one block, Sharpe drops to
roughly 0.7-0.8 on the remaining 14 blocks (still 10/14 positive).
roll=250 is consistently the weakest setting at every lambda tried
(0.71 / 0.50 / 0.05), meaning the shorter windows Zigma actually shipped
(120-180) were not an arbitrary lucky pick.

Verdict: NOT dead weight (unlike the sparse-ridge disagreement filter,
confirmed dead twice already), but smaller and more concentrated than its
current 5.0x weight assumes. Recommend downgrading the weight if this code
is revisited, not removing it outright. The one thing that would raise
confidence: checking whether block #12 corresponds to a specific, once-off
market event or is a recurring pattern type.

### 8. ALGO trend acceleration (curvature)
Inspiration: CookieAlgorists' own "future directions" slide (curvature,
acceleration, beyond plain slope). Applied to ALGO itself as an alternative
to the plain 5-day reversal / relative-reversal signals already in Sigma16
/ Sigma17. accel_t = slope(W-day window ending today) minus slope(the prior
W-day window), i.e. is the trend itself speeding up or slowing down.

Method: swept W in {3,5,8,10,15,20}, both follow and fade directions, full
block breakdown across days 120-499.

Result: W=3,5,8 weakly agree on fade (Sharpe 0.37, 0.24, 0.28). W=10 and
W=15 flip to favour the opposite direction (-0.27, -0.13). W=20 jumps back
to fade at the highest Sharpe in the grid (0.66) with no smooth transition
from its neighbours. Every Sharpe in the entire grid is below 0.7 -- well
under anything this project treats as a real effect (seed pairs ~6-7,
birth gate's validated ~+50 point average).

Verdict: REJECTED. A flip in the middle of the grid plus a discontinuous
jump at the edge is the same shape as #3 and #5's fitting-artifact
signature, and the effect sizes are too weak to matter even where the sign
agrees.

### 9. Cointegration-reweighted lead-lag matrix (seed-pair boost)
Background diagnostic (done first, before building anything): is the dense
lead-lag matrix L stable over time? Split days 1-500 into two independent
halves and compared L fit on each. Entry-wise correlation between halves:
only 0.121 for the general population, sign agreement 54.0% (barely above
a coin flip), and ZERO overlap between the two halves' top-20-by-magnitude
entries. This is itself an important finding: individual L entries carry
almost no standalone persistence; the dense matrix's real edge is a pure
Grinold's-law breadth effect (many near-zero-persistence entries, summed).
But the SEED PAIRS specifically broke this pattern: their 14 directed
L-entries showed correlation 0.343 and sign agreement 64.3% between the
same two halves (vs. a random-same-size-draw baseline of 0.098 mean
correlation -- only 20% of 500 random draws beat the seed-pair number).
Gray-tier pairs, checked the same way, showed NO such advantage
(correlation -0.019, worse than random) -- confirming the effect is
specific to the hand-verified seed pairs, not cointegration status in
general.

Idea: since seed-pair L-entries are genuinely more trustworthy, boost them
(multiplicatively, as an overlay on the existing dense matrix, NOT a
replacement/sparsification) rather than trusting the matrix uniformly.

Method (forecast-quality stage): seed-pairs-only boost mask, swept
boost in {0,1,2,3,5,8,12,20}, evaluated as cross-sectional correlation and
sign hit-rate against next-day realized returns, fully causal, full
15-block breakdown across days 120-499 (not a single train/test split).
Result: clean, wide, unimodal plateau -- correlation rose from 0.0611
(boost=0) to a peak of 0.0648 at boost=3, staying in a stable 0.0630-0.0648
band across boost=1-5, then decaying symmetrically at boost=8/12/20. This
is the best-shaped (least spike-like) result of anything tried this
session.

Method (real backtest stage): built Sigma16_LLboost.py, identical to the
real Sigma16.py except the dense lead-lag matrix's 14 seed-pair entries are
multiplied by (1+3.0) after the existing expanding/recent blend, every
rescan. Scored both files on 251-500 and 501-750 via Evalto, isolated
directories.

Result:
                Sigma16 (baseline)   Sigma16_LLboost
  251-500 score:      747.73              732.70   (-15.0)
  501-750 score:      786.45              747.98   (-38.5)
Worse on BOTH windows, despite the forecast-quality premise checking out.

Why the disconnect: the isolated diagnostic tested a simplified lead-lag
path (single dense matrix, boosted, correlated directly against next-day
returns). The real Sigma16 signal path is more layered -- expanding/recent
blend, small-signal thresholding, and critically a GLOBAL normalization
(`signal_sd = raw_ll_signal[1:].std()` across all 49 names) before the
tail-regime hysteresis transform. Boosting 14 of ~2450 entries inflates
that shared normalization denominator, which quietly shrinks the effective
z-score for every OTHER name's lead-lag vote -- an interaction the
diagnostic (which never modelled the shared normalization step) could not
have caught.

Verdict: REJECTED as implemented. The underlying premise (seed-pair
L-entries are more stable) held up under real scrutiny and is the
best-evidenced positive statistical finding of this whole session; the
specific mechanism used to act on it (a multiplicative boost inside a
matrix that then gets globally renormalized) was the wrong lever, and a
smaller boost would very likely just be a smaller version of the same
distortion rather than a fix. If revisited, the boost would need to be
added as a separate term OUTSIDE the shared normalization denominator,
not baked into the matrix that gets normalized.

### 10. SigmaB14's ALGO selector, rebuilt clean (agree-only reversal)
Background: a third party (via ChatGPT) sent SigmaB14, built off SigmaB10,
replacing the plain 5-day ALGO reversal with an adaptive selector between
that raw arm and a second "relative" arm (beta-residualize ALGO against the
equal-weight market, fade the residual's short-horizon cumulative move),
chosen by a causal shadow-PnL comparison with hysteresis. When asked
directly, ChatGPT disclosed that B14's architecture and constants were
selected after examining performance across days 251-750 -- i.e. both of
this project's two-window-bar windows were used to choose BETWEEN
architectures (B11 through B14), not just to tune one. This is the Zigma10
failure mode at the design-selection level rather than the runtime-code
level: causal at runtime, but the human iteration loop had already seen the
answer key. Scored via Evalto anyway for reference (SigmaB14 vs SigmaB10:
+47 on 251-500, +99 on 501-750) but treated as descriptive, not validating,
for exactly that reason.

Rebuild, in-house, in-sample only on days 1-500:
  - B14's actual mechanism (the shadow-PnL selector) was rebuilt from
    scratch and swept over window in {30,40,60} x deadband in {10,25,50}.
    Every one of the 9 configurations scored WORSE than simply using the
    relative arm alone (Sharpe 0.45-1.37 vs 2.13 fixed). REJECTED -- the
    selector doesn't just add unneeded complexity, it actively subtracts
    value, full stop.
  - The relative arm alone, independently swept (beta_window in
    {40,60,90} x horizon in {3,5,8}), showed a genuine, wide plateau:
    Sharpe 1.85-2.13 at horizon=3 across all three beta_windows, decaying
    monotonically at horizon=5 (0.54-0.69) and horizon=8 (-0.29 to 0.16).
    Note: bw=60/h=3 happens to match what B14 used, which I'd already seen
    in its code, so this is not a blind rediscovery -- but the plateau
    shape across a grid chosen independently is real corroboration that
    this specific ingredient (market-relative ALGO reversal) is genuine,
    separate from the contamination problem with B14's selection process.
  - Simpler combinations of raw + relative, no selector: a 50/50 blend
    scored Sharpe 2.17 (~matches relative-alone); "agree-only" (full size
    when raw and relative agree in sign, flat otherwise) scored Sharpe
    2.51-2.60 across every beta_window/horizon combo tested, with NO
    exceptions -- the most consistent plateau of anything tried this
    session.

Built SigmaB10_ALGOagree.py (SigmaB10's chassis unchanged, ALGO slot
replaced by the agree-only construction, bw=60/h=3/zlookback=120/thresh=0.5)
and scored it for real, both directly and via Evalto (identical numbers,
cross-confirmed):
                SigmaB10 (baseline)   SigmaB10_ALGOagree
  251-500 score:      744.80               712.17   (-32.6)
  501-750 score:      736.50               756.12   (+19.6)
Better Sharpe on BOTH windows individually (6.89 vs 6.47, 7.44 vs 6.53), but
a genuine mixed score result -- worse on 251-500, better on 501-750. Traced
the cause precisely: isolated on the exact 251-500 window, raw-alone hits
154.90/day vs agree-only's 117.90/day -- plain reversal had an unusually
strong run in that specific window, and going flat on disagreement
reasonably gives up some of that window-specific luck for better long-run
consistency. Not a bug; a real window-dependent tradeoff.

Verdict: GENUINELY INCONCLUSIVE, not rejected, not validated. B14's own
mechanism (the selector) is cleanly rejected regardless of what happens
next. The agree-only reconstruction is real progress -- properly derived
using only 1-500, beats B14's actual selector in every test, and its
501-750 result is a genuinely clean first look, unlike anything B14 itself
reported -- but it only wins one of the two available windows, and with
only two 250-day windows to judge from, that's a coin flip's worth of
evidence either way. Deliberately NOT chasing a sixth variant (e.g. partial
sizing on disagreement instead of fully flat) to try to force a two-window
win: iterating configurations against the same fixed windows until one
clears both is the exact process that produced B14's contamination problem
in the first place, just done to ourselves in slower motion. The correct
next step is a genuinely new data point, not another pass through the same
500 days -- score SigmaB10 and SigmaB10_ALGOagree, unchanged, on days
751-1000 once available, and let that break the tie. Until then: keep
SigmaB10 live, keep this candidate on file, ship neither.

### 11. ALGO-shock-conditional lead vector (from Sigma7p_robust_fit500) -- VALIDATED, now Sigma18
Background: a third party (via ChatGPT) sent Sigma7p_robust_fit500.py, built
off Sigma7p (seeds + dense lead-lag only, no gray tier, no birth catcher).
This one's disclosed methodology was meaningfully cleaner than SigmaB14's:
structural coefficients (seed eligibility, the lead-lag matrix, an "ALGO
lead vector," and the hedge-beta vector) are fit on an expanding window and
explicitly frozen at day 500 (`nt<=500` gate on rescanning, verified
directly in the code), while hyperparameters (BAND=0.40, RESCAN=10,
LLW=0.75, 4% antisymmetric emphasis, 10% snapshot blend, ALGO threshold and
weight) were chosen via internal folds strictly inside days 1-500
(120-250, 250-375, 375-500) before ever looking at 501-750. The one honest
caveat disclosed: 501-750 was "subsequently inspected repeatedly" once
available, so some risk of research-decision-level (not coefficient-level)
influence remains, but this is a materially smaller and more honestly
flagged risk than SigmaB14's multi-architecture search.

Scored directly (own harness, not Evalto, per the "just eval yourself"
instruction): Sigma7p baseline 626.3 / 621.3 vs the received file's full
bundle 728.2 / 773.3 -- a strong two-window improvement, but with 7 distinct
changes bundled together.

Ablation (one change at a time, vs the 626.3/621.3 baseline):
  RESCAN 10 alone:        +10.6 / +7.0
  BAND 0.40 alone:        -13.4 / -23.6   (negative alone, both windows)
  LLW 0.75 alone:         +11.1 / +6.6
  row/column centering:   +29.1 / +11.0
  4% antisymmetric:        +6.9 / +3.0
  10% snapshot blend:     +27.2 / -10.5   (window-inconsistent)
  ALGO lead vector alone: +30.1 / +104.9  (~69% of the full bundle's
                                            501-750 improvement, from one
                                            change)
The ag vector -- when ALGO's own contemporaneous return is an unusually
large shock, directionally nudge every other name's lead-lag forecast --
was clearly the dominant driver. Several of the other 6 changes were weak,
inconsistent, or (BAND) net negative alone despite surviving in the bundle.

Neighbourhood test on the ag vector's own three parameters, isolated on
otherwise-base Sigma7p (19 configs total):
  threshold in [0.5, 2.0] (6 values): every one beat the no-ag baseline on
    BOTH windows, no exceptions (251-500: 628.4-661.8; 501-750: 664.0-725.9)
  weight in [0.5, 4.0] (7 values): same result, no exceptions (251-500:
    630.3-659.8; 501-750: 652.5-725.4), rising to a plateau at weight 2-3
  blend in [0.0, 0.30] (6 values): flat response, barely matters at all
    (251-500: 654.4-658.6; 501-750: 720.1-726.9) -- not load-bearing,
    could be dropped
This is the widest, cleanest, most exception-free plateau found in this
entire alpha-exploration pass, comparable to or exceeding the seed-pair
L-entry stability finding (#9). The received file's actual calibration
(threshold=1.0, weight=2.0) sits in the middle of the validated region, not
at an edge -- consistent with it having been chosen via honest in-sample
folds rather than a lucky peek.

Grafted just this one piece (nothing else from the bundle) onto SigmaB10's
fuller chassis (seeds + gray tier + birth-catcher + lead-lag, not the bare
Sigma7p core), converted from frozen-at-500 to always-rescanning on the same
RESCAN=20 cadence as the rest of the book. Built as Sigma18.py (renamed from
SigmaB10_AGvector.py after this validation). Scored on both windows:
                SigmaB10 (baseline)      Sigma18
  251-500 score:      744.80              821.71   (+76.9)
  501-750 score:      736.50              825.41   (+88.9)
Both windows improve by a similar, balanced margin -- not the lopsided
one-window-wins-one-loses shape that sank Sigma17 relative to SigmaB10.
Sharpe improves on both windows too (6.47->7.22, 6.53->7.36), so this is not
just riskier positioning.

Verdict: VALIDATED, the strongest result of this entire alpha-exploration
pass. Passed disclosure scrutiny, ablation (isolated from 6 weaker/negative
bundled changes), neighbourhood testing (19 configs, zero exceptions), and
a clean graft onto the fuller chassis with both windows improving in
balance. Now the best-by-backtest model in the lineage (see Model
Evaluation Summary.txt / Model Performance Evaluation.txt). Not yet tested
live -- Sigma16 is the standing reminder that clearing the two-window bar
and a neighbourhood-plateau check is not a live guarantee, so this should
still be treated as backtest-validated, not proven, until it has a live or
751-1000 data point.

### 13. Five-round Track A push against Sigma19 -- ALL REJECTED, baseline unchanged

Unlike entry 12, this entry is a firsthand record: run through the full
three-agent loop (optimizer proposes + validates on 1-500, evaluator scores
1-500 and the true 501-750 holdout, coordinator judges), with every baseline
number cross-checked against Sigma19's own documented 831.58 / 836.73 before
any candidate comparison was trusted. Baseline was `Model List/Sigma19.py`
throughout; zero candidates were promoted.

Round 1 -- cross-sectional trend/momentum overlay (rank non-ALGO names by
trailing return, long winners/short losers) added atop the existing
mean-reversion book. REJECTED on internal 1-500 folds alone: worse on 3 of 4
folds, mean fold -2.8%, official 251-500 -9.6%. Never reached held-out eval.

Round 2 -- idiosyncratic residual-after-2-factor-hedge self-mean-reversion,
trading only names left over after pairs/gray tier claim theirs. REJECTED on
internal folds: flat/noise-level (mean fold -0.24%, official window +0.32%,
no consistent direction across a small parameter sweep). Never reached
held-out eval.

Round 3 -- binary/continuous volatility-regime gating or sizing applied to
the existing signals (shrink or flatten exposure when short-term realized
vol rises relative to its own baseline). First attempt produced a baseline

Round 4 -- moved the existing small-signal lead-lag threshold (LL_THRESH=

Round 5 -- same underlying idea as round 4 (denoise `linear_full`), redone

Verdict: NET NEGATIVE PUSH, baseline holds. Rounds 1-3 failed cheaply
(internal folds, never reached holdout). Rounds 4 and 5 both targeted the
same underlying idea -- that `linear_full`, the dominant 90%-weight
expanding-history lead-lag component, is currently completely unfiltered and
might benefit from denoising -- via two structurally different mechanisms,
and both produced real, methodologically distinct 251-500/internal-fold
gains that failed to generalize to 501-750, with two different failure
shapes (regime-fragile single-block cancellation, then broad uniform
non-reversing underperformance). This is a reasonably strong two-mechanism
negative result for per-element thresholding/denoising of `linear_full`, not
a "wrong constant" problem -- a third variant of the same idea (another
cutoff function on `linear_full`) is not recommended without a genuinely
different, economically-motivated rationale rather than another magnitude
threshold. Two adjacent levers were never touched by either round and remain
open if this area is revisited: the 90/10 blend weight itself between
`linear_full` and `linear_recent`, and whether `linear_recent`'s own existing
hard threshold (LL_THRESH=0.04) is well-calibrated on its own terms -- both
sit adjacent to real (if ultimately overfit) signal found this push. Six
candidate files remain in `Model List/candidates/` for reference
(Sigma19_CrossSectionalMomentum.py, Sigma19_IdioResid.py,
Sigma19_RegimeScale.py [voided attempt], Sigma19_VolGate.py [clean rerun],
Sigma19_LLThreshPostBlend.py, Sigma19_LLFullSoftThresh.py); none promoted,
`Model List/Sigma19.py` unchanged as Track A's best model.
